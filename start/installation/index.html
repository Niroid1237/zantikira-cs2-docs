    Установка¶

    Требования¶

    • Загруженный debug.dll, alpha.dll или release.dll.
    • Включённый чекбокс enable scripting во вкладке Lua.
    • Файл скрипта в папке скриптов ZantiKira.

    Папка скриптов¶

    Основной путь:

    %LOCALAPPDATA%\zantikira\scripts

    Если LOCALAPPDATA недоступна, используется %APPDATA%\phantom\scripts, затем .\scripts рядом с процессом.

    Относительный путь в конфиге разрешается от этой папки:

    { "path": "my_script.lua", "enabled": true }

    Абсолютный путь разрешён только внутри папки скриптов. Выход через .., junction/symlink или другой корень отклоняется. Поддерживаются только .lua; файл должен быть непустым и не больше 2 MiB.

    Список скриптов¶

    Скрипты не обнаруживаются автоматически. Менеджер читает только lua.script list из активного конфига — custom-поле с массивом записей:

    [
  { "path": "bhop.lua", "enabled": true },
  { "path": "overlay.lua", "enabled": false }
]

    В JSON-файле конфига это поле лежит внутри fields под ключом 7605c6c2. Ограничения: до 128 записей, путь до 512 символов.

    Добавлять записи можно через вкладку Lua:

    1. Введи имя файла или путь в поле под Scripts.
    2. Нажми add.
    3. Нажми reload — только после этого скрипт запустится.
    4. Для сохранения списка сохрани конфиг в Settings → Config.

    enabled выключает отдельный скрипт. Глобальный enable scripting выключает весь рантайм и выгружает все state.

    FFI¶

    allow ffi (unsafe) — глобальный флаг активного конфига, по умолчанию выключен. Он сохраняется вместе с конфигом. При переключении все Lua state закрываются и создаются заново.

    • Выключен: нет io, os, debug, package, dofile, loadfile, ffi; require всегда выбрасывает ошибку.
    • Включён: полные стандартные библиотеки LuaJIT, включая ffi и package; package.path начинается с папки скриптов.

    Подробнее: безопасность.

    Перезагрузка¶

    Скрипты перезагружаются:

    • кнопкой reload во вкладке Lua;
    • при добавлении/удалении/выключении записи в списке;
    • при смене enable scripting или allow ffi;
    • при загрузке или сбросе конфига.

    При перезагрузке вызывается shutdown, затем state закрывается. Если скрипт падает во время create_move или paint, закрывается только его state; ошибка попадает в лог, остальные скрипты продолжают работу.
