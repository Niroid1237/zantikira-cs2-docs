# Ограничения

## Текущий P0

Реализованы только:

- события `create_move`, `paint`, `ui`, `shutdown`;
- `cmd`: кнопки, view angles, forward/left/up move, номер команды, tick;
- `z.math`: векторы, углы, FOV, distance;
- `z.globals`: curtime, tick_count, is_in_game, frame_time, fps;
- `z.render`: прямоугольники, линии, круги, текст, `world_to_screen`, измерения;
- `z.ui`: окна в стиле ImGui на `xui`, checkbox, slider, combo, text input,
  кнопка, текст и раскладка;
- `z.settings`: список, чтение и запись primitive-настроек по `category, name`;
- `z.engine`: `is_connected`, `is_in_game`, `client_cmd`;
- `z.entitylist`: снимки локального игрока и живых игроков, health, team,
  armor, weapon, origin, eye position, velocity, flags, sim_time, а также
  motion-история на 64 тика;
- `z.trace`: луч и hull с fraction, позицией, нормалью и индексом игрока;
- `z.time`, `z.buttons`, `z.log`, `print`;
- FFI-режим с полным стандартным LuaJIT или безопасным набором без файлов/ОС.

Не реализованы:

- полный список не-игровых сущностей, кости и хитбоксы;
- engine prediction, autowall, backtrack, автоматическая проверка видимости;
- custom-поля настроек через API (списки скинов/агентов, список скриптов);
- HTTP и любые сетевые API;
- загрузка шрифтов, картинок и своих draw-list;
- clip/scissor, градиенты, blur;
- `z.render` вне `paint`;
- API перезагрузки скриптов из Lua;
- асинхронные события и yield;
- индивидуальные разрешения на скрипт.

## Лимиты

| Параметр | Значение |
|---|---:|
| Размер скрипта | 2 MiB |
| Записей в списке | 128 |
| Длина пути | 512 |
| Лог в памяти | 256 записей |
| Лог в UI | 11 записей |
| Длина сообщения | 2048 |

## Время жизни

- `cmd` живёт один `create_move`; после callback — ошибка.
- `z.render` живёт только внутри `paint`.
- `z.ui` живёт только внутри `ui`; окно должно быть закрыто до возврата из
  callback. При закрытом меню окна видны, но ввод обычно недоступен, пока
  курсор захвачен игрой.
- `z.entitylist` отдаёт копию данных; таблицу можно хранить, но её значения не
  обновляются после создания снимка.
- State скрипта живёт до ошибки, reload, выгрузки или смены конфига.
- `shutdown` вызывается при штатном закрытии, но не после runtime-ошибки.
- Состояние окон скрипта сбрасывается при reload: позиции, combo и text input
  не переносятся в новый state.

## Произвольные команды

`z.engine.client_cmd()` выполняет клиентскую команду сразу. Это не sandbox и не
ограниченный набор movement-функций: команда может изменить настройки, выйти из
игры или выполнить `quit`. Ответственность за строку полностью лежит на скрипте.

## Чего нет в конфиге

- Автозапуска из папки.
- Сканирования `.lua`.
- Облачной синхронизации.
- Allowlist/подписи.
- Скрытого запуска в обход списка.

Список — единственный источник истины. Если путь убрали из конфига и нажали
`reload`, скрипт больше не работает.
