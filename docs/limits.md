# Ограничения

## Искусственные лимиты сняты

В `0.7.0` убраны фиксированные пределы, которые резали скрипты без причины:

| Parameter | Status |
|---|---|
| Размер `.lua` | нет лимита; ограничен памятью процесса |
| Записей в `lua.script list` | нет лимита |
| Длина пути скрипта | ограничена файловой системой и Windows |
| Лог в памяти | нет фиксированного числа записей |
| Лог во вкладке Lua | показываются все текущие записи |
| Длина сообщения `z.log` | нет лимита |
| Длина client command | нет лимита, кроме памяти и NUL |
| Строковые настройки | нет лимита `4096` |

Лог, список скриптов и очереди рендера растут вместе с потреблением памяти.
Это не «бесплатно»: скрипт, который пишет миллионы строк или добавляет
миллионы записей, может занять память процесса.

## Практические границы API

| Parameter | Limit | Description |
|---|---:|---|
| `z.entitylist.history` | `64` | последние motion-снимки на игрока |
| `z.entitylist.history` по умолчанию | `16` | если `limit` не указан |
| `z.combat.backtrack_records` по умолчанию | `16` | если `limit` не указан |
| `z.settings` category/name | `1..120` байт | каждое поле отдельно |
| `z.settings` путь `category.name` | `3..241` байт | короткая форма |
| `z.net` timeout | `1..600000` мс | HTTP, TCP, UDP |
| `z.net` receive | `64 MiB` за вызов | защита от случайного выделения |
| `z.ui` окно | минимум `160×100` | размер окна |
| `z.engine.predict` | без вложенности | нельзя вызывать prediction внутри prediction |

У `backtrack_records` нет верхнего искусственного предела: вернётся столько
валидных записей, сколько реально хранит lag compensation. `limit` меньше `1`
поднимается до `1`.

## Время жизни

- `cmd` живёт один `create_move`; после callback — ошибка.
- `z.ui` живёт только внутри `ui`; окно должно быть закрыто до возврата из
  callback. При закрытом меню окна видны, но ввод обычно недоступен, пока
  курсор захвачен игрой.
- `z.entitylist` отдаёт копию данных; таблицу можно хранить, но её значения не
  обновляются после создания снимка.
- `image` и `font` — userdata-токены текущего Lua state. После reload их нужно
  загрузить заново.
- Отложенный draw-list хранит текстуры; не освобождай изображение до отправки
  команд.
- State скрипта живёт до ошибки, reload, выгрузки или смены конфига.
- `shutdown` вызывается при штатном закрытии, но не после runtime-ошибки.
- Состояние окон скрипта сбрасывается при reload: позиции, combo и text input
  не переносятся в новый state.
- Записи `z.combat` и `z.entitylist.history` — снимки. Они не превращаются в
  ссылки на живую сущность.

## Произвольные команды

`z.engine.client_cmd()` выполняет клиентскую команду сразу. Это не sandbox и не
ограниченный набор movement-функций: команда может изменить настройки, выйти из
игры или выполнить `quit`. Ответственность за строку полностью лежит на скрипте.

## Сеть и файлы без FFI

Выключенный FFI не означает отсутствие ввода-вывода:

- `z.net` открывает HTTP, DNS, TCP и UDP;
- `z.assets` читает файлы изображений и шрифтов по абсолютному пути;
- `z.settings` пишет настройки чита, включая custom-поля;
- `z.scripts.reload` перезагружает весь список.

Это сделано осознанно, но означает, что «безопасного» режима для чужого кода
нет. Подробнее: [безопасность](security.md).

## Чего нет в конфиге

- Автозапуска из папки.
- Сканирования `.lua`.
- Облачной синхронизации.
- Allowlist/подписей.
- Скрытого запуска в обход списка.

Список — единственный источник истины. Если путь убрали из конфига и нажали
`reload`, скрипт больше не работает.
