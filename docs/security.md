# Безопасность

## Модель доверия

ZantiKira не проверяет скрипты по подписи, не использует allowlist и не
отправляет их в облако. Скрипт — это код, который выполняется в процессе игры с
правами чита. Запуск полностью на риск пользователя.

Единственный барьер — глобальный чекбокс FFI:

| | FFI off | FFI on |
|---|---|---|
| `io`, `os`, `debug`, `package` | нет | есть |
| `dofile`, `loadfile` | нет | есть |
| `require` | всегда ошибка | обычный `require` |
| `ffi` | нет | есть |
| файлы и сеть | нет | через `io`/FFI |
| native-код | нет | да |

FFI off не является полноценной песочницей: Lua-код всё равно выполняется в
процессе игры и может, например, зациклиться или занять память. Но без FFI у
него нет штатного доступа к файлам, ОС и нативным вызовам.

`z.engine.client_cmd()` доступен и без FFI и может выполнить произвольную
клиентскую команду, включая `quit` или `disconnect`. `z.entitylist` не отдаёт
сырые указатели: только копии полей локального и живых игроков. `z.trace`
возвращает геометрию и controller index, без pawn/controller-указателей.

`z.settings` также доступен без FFI и может читать и записывать primitive-поля
настроек чита, включая боевые и визуальные. Это осознанный доступ к тому же
реестру, который использует меню; отдельного allowlist по настройкам нет.
Custom-поля (списки скинов/агентов, список скриптов) через API не читаются и не
пишутся. `z.ui` не получает raw-указатели и работает только внутри события
`ui`.

## Что делает FFI off

Открываются только:

```text
base (_G, coroutine, load, loadstring, pcall, ...)
table
string
math
bit
jit
```

Удаляются:

```text
io  os  debug  package  dofile  loadfile  ffi
```

`require` заменяется функцией, которая всегда выбрасывает ошибку. Поэтому
`require("ffi")` при выключенном флаге — ошибка загрузки скрипта, а не тихий
переход на полный рантайм.

## Что делает FFI on

`luaL_openlibs` открывает стандартные библиотеки LuaJIT, включая `ffi`, `io`,
`os`, `debug` и `package`. `package.path` начинается с папки скриптов, поэтому
локальные модули можно подключать через `require`.

В этом режиме скрипт может:

- читать и писать память процесса;
- вызывать функции из загруженных DLL;
- загружать новые DLL;
- читать и записывать файлы;
- завершить процесс через `os.exit`.

Не запускай чужие FFI-скрипты. Даже «безобидный» скрипт может писать в
произвольные адреса.

## Изоляция скриптов

- Один `lua_State` на скрипт.
- Ошибка закрывает только state упавшего скрипта.
- Остальные скрипты продолжают работу.
- При reload/выгрузке вызывается `shutdown`, затем state закрывается.
- После runtime-ошибки `shutdown` не вызывается: код упавшего скрипта не
  исполняется повторно.
- Окна `z.ui` и combo-overlay закрываются до уничтожения state, чтобы xui не
  сохранил указатель на данные выгруженного скрипта.

Изоляция не защищает от вредоносного кода: FFI-скрипт может изменить общую
память процесса или повредить чужие объекты.

## Файлы и пути

- Скрипты лежат в `%LOCALAPPDATA%\zantikira\scripts`.
- Относительный путь не может выйти за эту папку.
- Абсолютный путь разрешён только внутри неё.
- Только `.lua`, непустой файл, максимум 2 MiB.
- Список — до 128 записей, путь до 512 символов.
- Папка не сканируется: запускаются только пути из активного конфига.

## Рекомендации

1. Держи FFI выключенным, если скрипту не нужен native-код.
2. Читай код перед запуском.
3. Не запускай скрипты, которые просят отключить проверки или обещают
   «разблокировать» доступ к памяти.
4. Сохраняй конфиг с известным набором скриптов и сверяй его после загрузки.
5. Для экспериментов используй отдельный конфиг.
