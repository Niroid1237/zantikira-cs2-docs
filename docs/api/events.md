# events

Все события доступны через `z.events`:

```lua
z.events.create_move:add(function(cmd) end)
z.events.paint:add(function() end)
z.events.ui:add(function() end)
z.events.shutdown:add(function() end)
```

`add` — единственный метод события. Он принимает Lua-функцию и добавляет её в
конец списка. Один и тот же обработчик можно добавить несколько раз. Порядок
вызова — порядок добавления.

## create_move

| Property | Value |
|---|---|
| Arguments | `cmd` — временный userdata |
| Timing | после встроенного movement, до финального subtick-обнуления |
| Render | `z.render` разрешён, но команды откладываются до следующего кадра |
| UI | `z.ui` нельзя |
| cmd lifetime | только до возврата из обработчика |

```lua
z.events.create_move:add(function(cmd)
    cmd:set_button(z.buttons.jump, true)
end)
```

`cmd` действителен только до возврата из обработчика. Если сохранить его в
глобальную переменную и использовать в следующем тике, методы выбросят ошибку
`command is only valid while create_move is running`. Это защищает от записи в
уже освобождённый usercmd.

Если обработчик вызывает `set_forward_move`, `set_left_move` или `set_up_move`,
менеджер помечает тик как script-controlled. Встроенное обнуление base movement
в этом тике пропускается. Установка кнопок и view angles такого флага не даёт.

`z.engine.predict()` без явного `cmd` работает только здесь; `cmd` живёт до
конца этого обработчика и не должен попадать в отложенные callback.

## paint

| Property | Value |
|---|---|
| Arguments | нет |
| Timing | после встроенных оверлеев, до виджетов и меню |
| Render | `z.render` рисует сразу в текущий кадр |
| UI | `z.ui` нельзя |
| cmd | недоступен |

```lua
z.events.paint:add(function()
    z.render.line(0, 0, 100, 100, { r = 255, g = 80, b = 80, a = 255 })
end)
```

`paint` вызывается и при закрытом меню. Это основной обработчик для overlay.
Вне `paint` `z.render` не выбрасывает ошибку, а складывает команды в отложенную
очередь до начала следующего `on_present`.

Отложенные команды отправляются **до** Lua `paint` следующего кадра. Если нужен
порядок «фон → мой overlay», рисуй обе части в `paint` или используй отдельные
draw-list.

## ui

| Property | Value |
|---|---|
| Arguments | нет |
| Timing | внутри существующей пары `xui::begin`/`xui::end`, после окна меню |
| Render | `z.render` разрешён, но команды откладываются до следующего кадра |
| UI | `z.ui` обязателен для окон и виджетов |
| cmd | недоступен |

```lua
z.events.ui:add(function()
    z.ui.begin_window("my panel", 40, 40, 320, 200, true)
    z.ui.text("hello")
    z.ui.end_window()
end)
```

`ui` вызывается и при закрытом меню, поэтому окна скрипта остаются на экране.
Окна и виджеты используют текущий `xui`-контекст: тему, clipping, курсор и
очередь ввода. Окно нужно закрыть до возврата из callback.

Здесь нельзя использовать `cmd`. Для фонового overlay лучше `paint`, а не
`ui`: deferred-команды из `ui` появляются на следующем кадре и могут
перекрываться меню.

Подробности: [пользовательские окна](ui.md) и [настройки](settings.md).

## shutdown

| Property | Value |
|---|---|
| Arguments | нет |
| Timing | перед закрытием state при reload/выгрузке/смене конфига |
| Render | не рекомендуется; state всё равно закрывается |
| UI | `z.ui` нельзя |
| cmd | недоступен |

```lua
z.events.shutdown:add(function()
    z.log("bye")
end)
```

`shutdown` не вызывается после runtime-ошибки: в этом случае state закрывается
сразу, чтобы не выполнять код упавшего скрипта повторно. Для сохранения
состояния используй `z.settings` или файл, но помни: запись настроек не
сохраняет конфиг на диск автоматически.

## Ошибки и изоляция

- Ошибка в любом обработчике закрывает state этого скрипта.
- Другие скрипты продолжают работу.
- Ошибка пишется в лог ZantiKira и во вкладку Lua.
- Стек вызовов не прикладывается: сообщение Lua содержит источник и строку.
- Yield из `create_move`/`paint`/`ui` невозможен: вызов идёт через `lua_pcall`
  из C++.
- Окно, оставленное открытым в `ui`, принудительно закрывается после callback
  с предупреждением в логе.
- `z.scripts.reload()` и `z.settings.set("lua", "script list", ...)` только
  ставят reload в очередь; state не закрывается посреди callback.

## Порядок в кадре

```text
create_move:
  встроенный movement
  → Lua create_move
  → финальное subtick-обнуление (если Lua не управлял движением)
  → input apply
```

```text
frame:
  → отложенные команды z.render
  → reload, если он был запрошен
  → Lua paint
  → виджеты и меню xdraw
  → Lua ui (окна скриптов)
```

Точный порядок встроенных оверлеев зависит от кадра; `paint` всегда вызывается
после отложенной очереди и до `ui`.
