# Модули API

Ориентир по объёму — модульные Lua API современных читов. Имена и границы
модулей взяты как общая идея; реализация и документация у ZantiKira свои.

| Модуль | ZantiKira | Статус |
|---|---|---|
| events | `z.events` | готово |
| user_cmd | `cmd` | готово |
| math | `z.math` | готово |
| render | `z.render` | готово, базовый набор |
| globals | `z.globals` | готово, базовый набор |
| time | `z.time` | готово |
| input buttons | `z.buttons` | готово |
| logging | `z.log`, `print` | готово |
| engine | `z.engine` | готово, базовый набор |
| entitylist | `z.entitylist` | готово, живые игроки и motion-история |
| menu / windows | `z.ui` | готово, базовый набор виджетов |
| settings | `z.settings` | готово, primitive-поля |
| trace | `z.trace` | готово, луч и hull |
| cvars / netvars | — | позже |
| http / json / clipboard | — | не в P0 |

## Почему так

- `math` и `globals` не зависят от новых игровых смещений и уже проверяются
  компиляцией.
- `engine` и `entitylist` уже дают минимальный слой для проверки состояния
  игры, локального игрока и живых игроков. Для чужих pawn отдаются безопасные
  снимки с velocity/flags/sim_time и короткая история по тикам — этого
  достаточно для пользовательской экстраполяции, но не для engine prediction.
  Полный список не-игровых сущностей требует отдельных обёрток и инвалидации
  указателей.
- `z.trace` использует существующий trace-менеджер проекта и отдаёт только
  геометрию и controller index. Это один луч/hull, без penetration и без
  хранения ссылок на сущности.
- `z.ui` использует существующий `xui`, а не второй Dear ImGui context:
  отдельный UI-контекст конфликтовал бы с вводом, темой и clipping меню.
  `z.settings` работает через тот же реестр, что и конфиг, без raw-указателей.
- HTTP, JSON, clipboard и произвольные cvars/netvars расширяют поверхность атаки;
  их нельзя добавлять раньше стабильного ядра.

## Следующий порядок

1. `z.entitylist`: снимки, motion-история и `z.trace` уже готовы; следующий
   слой — helper-функции для backtrack/экстраполяции, если они нужны.
2. `z.render`: clip rect, больше примитивов.
3. `z.trace`: multi-point/penetration helpers с явными лимитами.
4. `z.menu`: `is_open`, `notify`.
5. `z.engine`: больше безопасных запросов состояния без произвольных команд.

Сейчас скрипты могут проверить `z.globals.is_in_game()` или
`z.engine.is_in_game()`, получить снимок через `z.entitylist.local_player()`,
массив живых игроков через `z.entitylist.players()`, историю через
`z.entitylist.history()` и сделать trace через `z.trace`. Не считай, что
таблица снимка или игровые указатели живут дольше одного события.
