    Безопасность¶

    Модель доверия¶

    ZantiKira не проверяет скрипты по подписи, не использует allowlist и не отправляет их в облако. Скрипт — это код, который выполняется в процессе игры с правами чита. Запуск полностью на риск пользователя.

    Даже при выключенном FFI API намеренно даёт сеть, чтение файлов как ассетов, запись настроек и перезагрузку списка скриптов. Выключенный FFI — это не песочница, а режим без прямого native-кода.

    Capability FFI off FFI on
    io, os, debug, package нет есть
    dofile, loadfile нет есть
    require всегда ошибка обычный require
    ffi нет есть
    чтение файлов только z.assets (изображения/шрифты) любые файлы через io/FFI
    запись файлов нет через io/FFI
    сеть z.net: HTTP, DNS, TCP, UDP z.net + io/FFI
    native-код нет да
    память процесса только API z.* произвольная через FFI
    клиентские команды z.engine.client_cmd z.engine.client_cmd
    настройки чита z.settings, включая custom z.settings + FFI

    Без FFI Lua-код всё равно может зациклиться, занять память, отправить данные в сеть или прочитать произвольный файл как изображение/шрифт. Изоляция state не защищает от вредоносного кода.

    Что делает FFI off¶

    Открываются только:

    base (_G, coroutine, load, loadstring, pcall, ...)
table
string
math
bit
jit

    Удаляются:

    io  os  debug  package  dofile  loadfile  ffi

    require заменяется функцией, которая всегда выбрасывает ошибку. Поэтому require("ffi") при выключенном флаге — ошибка загрузки скрипта, а не тихий переход на полный рантайм.

    При этом z.net, z.assets, z.settings, z.scripts и остальные модули z.* остаются доступны. Это не стандартные библиотеки LuaJIT, а обёртки чита.

    Что делает FFI on¶

    luaL_openlibs открывает стандартные библиотеки LuaJIT, включая ffi, io, os, debug и package. package.path начинается с папки скриптов, поэтому локальные модули можно подключать через require.

    В этом режиме скрипт может:

    • читать и писать память процесса;
    • вызывать функции из загруженных DLL;
    • загружать новые DLL;
    • читать и записывать любые доступные файлы;
    • завершить процесс через os.exit.

    Не запускай чужие FFI-скрипты. Даже «безобидный» скрипт может писать в произвольные адреса.

    Опасности без FFI¶

    Сеть¶

    z.net.http, z.net.dns, z.net.tcp_connect и z.net.udp работают всегда. Скрипт может отправлять наружу любые данные, которые смог получить, и принимать команды из сети. Ответ сервера — недоверенные данные; не исполняй его как код и не подставляй без проверки в client_cmd.

    Файлы¶

    z.assets.load_image, load_svg и load_font читают абсолютные пути без ограничения папкой скриптов. Это нужно для пользовательских ассетов, но означает, что скрипт может попытаться прочитать любой файл, который сможет декодировать как изображение или шрифт. Записи файлов нет.

    Сами скрипты по-прежнему ограничены папкой скриптов: путь проверяется через canonical path, .. и symlink/junction за пределы папки отклоняются.

    Настройки¶

    z.settings читает и пишет весь реестр, включая боевые настройки, скины, агентов и lua.script list. Отдельного allowlist нет. Запись списка скриптов может выключить или заменить выполняемый код после перезагрузки.

    Клиентские команды¶

    z.engine.client_cmd() выполняет произвольную клиентскую команду, включая quit, disconnect, bind и команды, меняющие состояние игры. Это не movement-API.

    Ресурсы¶

    Лог, список скриптов, история движения и очередь отложенного рендера не имеют жёстких счётчиков. Скрипт может занять память процесса. Бесконечный цикл в create_move или paint заблокирует поток игры; API не прерывает Lua по таймауту.

    Что API не отдаёт¶

    • z.entitylist, z.trace, z.combat возвращают только копии полей и геометрию. Pawn/controller-указатели, handle-ы и адреса наружу не попадают.
    • image и font — userdata-токены. Через них нельзя получить texture/SRV или native-указатель.
    • socket — userdata с ограниченным набором методов; дескриптор сокета не отдаётся.
    • draw_list — контейнер вершин и команд, без доступа к D3D11-объектам.

    Это снижает риск случайной порчи памяти, но не делает чужой скрипт безопасным: он всё равно управляет настройками, сетью и клиентскими командами.

    Изоляция скриптов¶

    • Один lua_State на скрипт.
    • Ошибка закрывает только state упавшего скрипта.
    • Остальные скрипты продолжают работу.
    • При reload/выгрузке вызывается shutdown, затем state закрывается.
    • После runtime-ошибки shutdown не вызывается: код упавшего скрипта не исполняется повторно.
    • Окна z.ui и combo-overlay закрываются до уничтожения state, чтобы xui не сохранил указатель на данные выгруженного скрипта.
    • Изображения удерживаются внутренним keepalive; шрифты принадлежат xdraw.

    Изоляция не защищает от вредоносного кода: FFI-скрипт может изменить общую память процесса или повредить чужие объекты, а скрипт без FFI — украсть данные через сеть или сломать конфиг.

    Файлы и пути¶

    • Скрипты лежат в %LOCALAPPDATA%\zantikira\scripts (fallback: %APPDATA%\phantom\scripts, затем .\scripts).
    • Относительный путь скрипта разрешается от этой папки.
    • Абсолютный путь разрешён только внутри неё.
    • Только .lua, файл должен существовать и быть непустым. Искусственного лимита размера нет.
    • Список скриптов не ограничен по числу записей.
    • Папка не сканируется: запускаются только пути из активного конфига.
    • Ассеты могут читаться по любому доступному пути.

    Рекомендации¶

    1. Держи FFI выключенным, если скрипту не нужен native-код. Это снижает риск, но не отменяет сеть, чтение ассетов и доступ к настройкам.
    2. Читай код перед запуском, даже если это «простой overlay».
    3. Не запускай скрипты, которые просят отключить проверки, обещают «разблокировать» память или присылают обфусцированный код.
    4. Не давай скриптам токены, пароли и пути к приватным файлам.
    5. Сохраняй конфиг с известным набором скриптов и сверяй его после загрузки.
    6. Для экспериментов используй отдельный конфиг.
